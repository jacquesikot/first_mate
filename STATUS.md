## Engine shape after 2026-08-20 (read before touching the orchestrator)

The control flow gained two primitives and two LLM decision points. A
session that only knows the pre-2026-08-20 engine will misread the loop.

- **`StepSpec.when` (a `Gate`)** — a shell probe the *daemon* polls before
  spawning a worker. The task sits in the new **`waiting`** status holding no
  session, no tmux window, no tokens and no worker slot; `GateState` persists
  progress so a restart resumes the same wait. Boot `reconcile` resumes
  `waiting` tasks. Step prompts must never sleep or poll — that is what
  gates replace.
- **`StepSpec.on_failure` (a `LoopBack`)** — on criteria failure the step
  cursor *rewinds* and every step from the target forward re-runs. The main
  loop is therefore index-driven, and `_run_step` returns `True` (advance) /
  `int` (rewind to that index) / `None` (resting state). **`bool` is a
  subclass of `int` in Python** — test `is not True` before treating a
  return as an index, or `True` reads as "rewind to index 1".
- **Failure ladder order:** attempt 1 → attempt 2 with the failure as
  context → criterion judgement (only with a loop edge, only after a
  non-progressing round) → `on_failure` rewind → escalate. A round is
  therefore *two* criterion evaluations.
- **`supervisor.py`** — investigates with read-only tools when a gate stalls
  or a step keeps failing. May rewrite `steps[i].when`; may **never** touch a
  criterion (no field and no function exists to — asserted by a test).
  Repairs are verified by re-probing before being committed.
- **`replan.py`** — an operator's free-text answer becomes a contract edit
  under the same `validate_contract` gate, never touching `goal`/`repo`, with
  the before-contract and a unified diff persisted.
- **`cleanup.py`** — never removes a worktree on its own; the clean-and-pushed
  bar plus `--force`. `fm clean` / `POST /tasks/{id}/cleanup` / the dashboard
  reclaim control are the entry points.
- **Guard:** `.fm/artifacts/` is always writable and git-invisible; lockfiles
  pass the hook while manifests still trip it (a step-boundary check catches
  real drift); a refusal answer rewrites the offending step prompt.

  **New `supervisor.py`** — a named LLM decision point that runs when a gate stalls. It investigates the real world with **read-only** tools (`gh pr view/checks/diff/api`, `gh run list/view`, `git log/rev-parse/status/diff/show`, file reads — asserted read-only by a test), then returns `gate_wrong` / `still_waiting` / `cannot_tell` with findings, reasoning, and a replacement probe.   **What was built** (PRD §6.2/§6.4/§6.5 updated to match):
  1. **Waiting primitive — gates.** New `StepSpec.when` (`Gate`: command, interval, ceiling, timeout, description). A gated step spawns no worker until its probe passes; the task sits in the new `waiting` status holding **no worker slot and no session**, so the semaphore is untouched and other tasks keep running. `GateState` persists probe count and `first_probe_at`, so a daemon restart resumes the same wait instead of granting a fresh ceiling (boot `reconcile` now resumes `waiting` tasks). Ceiling escalates with real options (`keep waiting` / `run the step anyway` / `abandon`) rather than retry/abandon. `validation.run_gate` reuses the criterion machinery — a gate is the same kind of machine-checkable fact, evaluated before the work rather than after.
  2. **Convergence loops — loop edges.** New `StepSpec.on_failure` (`LoopBack`: goto, max_iterations). On criteria failure *after* the existing retry, the orchestrator rewinds the step cursor to the named step and resets every step from there forward, so a fix is genuinely re-made, re-pushed and re-verified rather than just re-validated. The main loop became index-driven to allow the rewind. Two brakes: `max_iterations`, and a **no-progress check** — `_failure_signature` hashes the failing criteria's ids/exit codes/output, and an identical signature two rounds running stops the loop and asks, so it can't spin. The rewound step is injected with a `loop_note` carrying the round number and the failing evidence verbatim.
  3. **Answers that change something.** `store._apply_refusal`: a non-allow answer to a guard question is appended to the offending step's prompt as an `OPERATOR CORRECTION` (binding, "do not attempt that again, do not re-ask"). New `replan.py` — a named LLM decision point turning free-text answers into a **contract edit**: only `steps`/`criteria`/`scope_*`/`tripwires`/`context` are editable (never `goal`/`repo`), the result must pass the same `validate_contract` gate as a fresh contract, and the before-contract plus a unified diff are persisted as task artifacts (`contract-before-<qid>.json`, `replan-<qid>.diff`) so the operator can audit exactly what their words did. Structured actions handled mechanically first, no LLM: `accept and continue`, `loop again`, `keep waiting`, `run the step anyway`, `retry`.
  4. **Guard: four fixes, so mechanics stop being interruptions.** (a) **Scratch space** — `.fm/artifacts/` is always writable, needs no scope entry, and is hidden from git via the *common* git dir's `info/exclude` (`git rev-parse --git-common-dir`; the per-worktree exclude is not read by `git status` — found by testing), so a worker's own draft can never reach a diff or a commit; out-of-scope blocks now name it as the alternative. (b) **Fingerprinting** — `question_fingerprint` keys guard questions on the *situation* (tripwire + paths), not the agent's prose, since one block hit by three generations yields three differently-worded questions about one decision; an equivalent question is auto-answered from the prior one and the worker is told to **continue, not stop**, recorded as a `question_auto_answered` event. (c) **Refusals edit the prompt** (above). (d) **Manifests vs. lockfiles** — `DEP_MANIFEST_NAMES` now holds only files that *declare* dependencies; derived lockfiles moved to `LOCKFILE_NAMES` and pass the hook, because a bare `bun install` in a fresh worktree rewrites one purely to populate `node_modules` and that isn't something an operator can meaningfully approve. The guarantee is kept by a new step-boundary check, `orchestrator._lockfile_drift`, which asks once if a lockfile actually appears in the diff.
  5. **Prompts taught the new primitives.** The scoping prompt now has a "Waiting and iterating — use the contract, not the step prompt" section that explicitly forbids proposing a single pass or asking the operator to choose between a single pass and a polling loop, and tells it to express review-driven work as fix → push → (gate) verify with an `on_failure` edge. (This is what produced the "two things I need from you" prompt Jacques hit — the assistant was asking him to work around a missing primitive.) The worker prompt gained: an already-answered `fm ask` reply is binding, do not stop and do not re-ask; write your own artifacts to `.fm/artifacts/`; never poll or sleep for something slow, the gate already handled it.

## Decision log

Decisions made outside the PRD, dated, with rationale. PRD §7 constraints are settled and not repeated here.

- **2026-08-20** — **Worktree removal is never automatic; dependency removal can be.** Deleting a worktree can destroy work that exists nowhere else, so it always takes an explicit ask (notice → `fm clean` / dashboard control) and always passes the clean-and-pushed bar first. Dependency and build directories are a different category: they are regenerable by definition, they are ~96% of a worktree's size, and losing them costs one install — so they may be dropped from a kept worktree and on an idle timer. The distinction to hold onto is *irreplaceable vs rebuildable*, not *big vs small*.
- **2026-08-20** — **Indeterminate counts as unsafe.** If `git status` or the pushed-ness check cannot be established, that is a blocker, not a pass. The failure mode being avoided is a deletion justified by a check that silently returned nothing — which is exactly the `--not --remotes` bug this work found.
- **2026-08-20** — **Task state is never deleted, only archived.** `~/.firstmate/tasks/**` is kilobytes and is the audit trail; every diagnosis in this session came from it. Archiving after 14 days keeps `tasks/` browsable without ever discarding evidence. Smoke runs are the one genuinely throwaway thing and are pruned by age.
- **2026-08-20** — **Idle is measured from the worktree, not from `.git`.** Any background git command writes inside `.git`, so including it in the freshness signal made a long-abandoned worktree look permanently active and the idle timer unable to fire. Only the worktree directory plus `.git/HEAD`/`index` count.
- **2026-08-20** — **The supervisor may judge a criterion, never edit one.** Escalating immediately on an unsatisfiable check is strictly better than looping five times to reach the same place with less information. But the asymmetry with gates holds: a gate is First Mate's instrument, a criterion is the operator's statement of what they wanted. So the criterion path is diagnosis-and-recommendation only, and that is structural rather than prompt-level — no `new_command` on `CriterionDiagnosis`, no `apply_criterion_repair`, no verdict that means "apply my fix". Acting on the recommendation happens through the escalation, where the operator's free text already reaches `replan.py`.
- **2026-08-20** — **Only a confident, evidenced "impossible" stops a loop.** Looping is cheap; stopping a job that would have succeeded is not. So `low` confidence does not block the loop, and an `unsatisfiable` verdict with empty findings is rejected outright — otherwise "this can never pass" becomes an easy way to give up. The prompt also states explicitly that unsatisfiable means impossible, not merely hard or not-yet-done, with `needs_more_work` as the stated default.
- **2026-08-20** — **Criterion judgement only where it changes the outcome.** The first cut consulted the supervisor on every twice-failed step, which is an LLM call on every ordinary test failure (and hung the test suite on real `claude` calls). Narrowed to: the step has a loop edge, at least one round has already run, and this round's failure signature is identical to the last. That is precisely the moment `_loop_back`'s no-progress brake would have stopped anyway — so the same stop now arrives with an explanation instead of a shrug, at no extra cost in the common case.
- **2026-08-20** — **`fm serve` claims the port before claiming success.** Printing a success line and rewriting `daemon.json` before the bind meant a failed restart was indistinguishable from a successful one, and left the operator running old code while believing otherwise. Fail loudly, name the conflicting pid, and leave the existing pointer intact.
- **2026-08-20** — **The supervisor may fix instruments, never the definition of done.** A gate is First Mate's own measuring device: if the measurement is wrong, correcting it is a runtime decision and should not cost the operator an interruption. A completion criterion is the operator's statement of what they wanted, so it is untouchable. Enforced in code (`apply_gate_repair` reaches only `steps[i].when`) rather than trusted to the prompt, because a prompt-level rule is exactly what a confused model ignores. Consequence worth naming: a bad diagnosis can waste a wait or skip one, and *cannot* make a failing job look successful.
- **2026-08-20** — **A gate repair must be verified before it is trusted.** The supervisor's new probe is run immediately; if it doesn't pass, the original gate is restored and the repair is logged as rejected. Otherwise a confident-sounding diagnosis would silently swap the thing being waited for on the strength of nothing but its own confidence. Same reasoning as the loop's no-progress brake: autonomy needs a check that the autonomous action actually worked.
- **2026-08-20** — **A trivially-true replacement probe is rejected.** `true`/`exit 0`/`:` would technically "open the gate" while deleting the precondition and pretending it was checked. If the honest answer is "there is nothing left to wait for", the supervisor must say so explicitly via `drop_gate` — which is auditable — rather than smuggling it in as a probe that always passes.
- **2026-08-20** — **Gate repairs notify, they don't ask.** Non-blocking `fyi` plus a diagnosis artifact and a contract amendment. Asking would reintroduce exactly the interruption this was built to remove; silence would let a wrong repair pass unnoticed. Jacques's standard is that First Mate handles mechanics itself and tells him after.
- **2026-08-20** — **Waiting is a first-class orchestrator primitive, not a worker behaviour.** A worker cannot wait well: polling costs context, and 25 minutes of `gh pr checks` walls a session that has done no work. So a step declares a `when` gate and the *daemon* waits — task in `waiting`, no session, no slot, progress persisted across restarts. Corollary, enforced in both prompts: step prompts must never sleep or poll for minutes. Rejected alternative: exempting poll turns from the wall count and raising `worker_timeout_s`, which would still hold a worker slot for half an hour and still burn tokens.
- **2026-08-20** — **Convergence loops belong in the contract, bounded twice.** Review-driven work is iterative by nature, so `on_failure: {goto, max_iterations}` makes it declarative and autonomous. An autonomous loop that cannot stop is worse than no loop, hence two independent brakes: the iteration cap, and a failure-signature comparison that stops a loop whose rounds are identical. Deliberately *not* asking the operator per round — that was the thing being fixed.
- **2026-08-20** — **The loop edge sits below the retry rung, above escalation.** Order is: attempt 1 → attempt 2 with the failure as context → `on_failure` rewind → escalate. A failing criterion is often a *fresh* fact (a reviewer found something new) rather than a flawed attempt, so retrying the same step twice first is still right; the rewind is what handles the new fact. This is why a round costs two criterion evaluations, which surprised the first version of the tests.
- **2026-08-20** — **Every answer must change something mechanically, or it will be asked again.** The old code amended prose and widened globs only on "allow", which made a refusal a no-op and put the operator in a loop whose only exit was saying yes. Now: allow widens, refusal rewrites the step prompt, and anything else goes to `replan.py`. Rejected alternative: recording free text for the next worker to interpret — that's what was already happening, and it demonstrably didn't work.
- **2026-08-20** — **A re-plan may not touch `goal` or `repo`, and may not neuter a criterion.** A stuck step is not a mandate to redefine the task; if the contract's identity were editable it would stop being a contract. Validation runs the same `validate_contract` gate as fresh scoping, the prompt forbids "relaxing" a check to `true`/`exit 0`, and the before-contract plus a unified diff are persisted so a bad re-plan is visible and revertible.

The browser follows over the WS `scoping` frame plus a poll while `thinking`. `POST /scoping/{id}/message` takes `{"wait": true}` for callers that want the old synchronous shape (tests, any future CLI use).
- **2026-08-19** — **Terminal `fm task "<goal>"` stays contract-first, deliberately not task-first.** It is a synchronous PTY conversation; creating a task up front would leave a phantom `scoping` task whenever the operator Ctrl-Cs out of the chat, and the daemon has no way to observe that exit. The asymmetry is intentional: task-first exists because the *browser* flow is asynchronous and the conversation needs somewhere to live.
- **2026-08-19** — **Terminal chat statuses (`approved`/`abandoned`) are sticky against in-flight turns.** Found live: abandoning a task while its first scoping turn was running let the landing turn flip the chat back to `awaiting_operator`. `advance` now re-reads `scoping.json` before writing the post-turn status and yields to a terminal status found there; the reply is still recorded, it just doesn't reopen the conversation.
- **2026-08-19** — **Assistant-authored text renders as markdown, via our own renderer, from React elements only.** Scoping replies, worker questions, handoff briefs and contract `context` are all written by Claude in markdown. `dashboard/src/markdown.tsx` is ~300 lines of the subset Claude actually emits and adds no runtime dependency (the dashboard still ships React and nothing else). It never touches `innerHTML`, so assistant output cannot inject markup; anything unrecognised falls through as text, so it can never silently drop content. Emphasis uses CommonMark-ish flanking because Claude writes `scope_in`/`max_diff_lines` constantly and naive rules ate the underscores. Single newlines render as `<br>` (chat convention), not spaces.
- **2026-08-19** — **The page never scrolls horizontally; wide content scrolls inside its own box.** `.content` carries `overflow-x: hidden` as a hard backstop and every wide surface (diff, code, table, tmux pane) gets its own `overflow-x: auto` container. Rationale: a horizontally scrolling page hides the whole left column, and no amount of per-component care prevents one long token from reintroducing it. Layout that must respond to width lives in CSS, not inline styles — an inline `display` beats a media-query class (found live: the sidebar footer survived the narrow-width collapse).
- **2026-08-19** — **`.fm/` and build caches are excluded from the operator's diff and from diff-tripwire totals** (`gitops.is_review_noise`). First Mate's own per-worktree state is orchestration, not the work under review; counting it would also charge the operator's `max_diff_lines` budget for our hook scripts. Filtering lives in `exec/gitops.py`, keeping the "only gitops touches git" boundary intact.
- **2026-08-19** — **`uvicorn[websockets]` class of bug: real-transport checks are required for transport features.** The `/ws` 404 was invisible to FastAPI's TestClient; live browser verification caught it. Phase 4+ features with real transports (Slack socket mode) should get at least one real-connection smoke.
